# 11 — 部署指南

## 构建站点

```bash
npm run build
```

默认输出到项目根目录的 `dist/` 文件夹（可通过 `outDir` 配置修改）。

---

## 部署设置

大多数平台需要以下构建设置：

| 设置项 | 值 |
|--------|-----|
| **构建命令** | `astro build` 或 `npm run build` |
| **发布目录** | `dist` |

## 部署流程

### 方式一：通过 Git 自动部署（推荐）

1. 将项目推送到 GitHub/GitLab/Bitbucket
2. 在托管平台（Netlify/Vercel 等）导入 Git 仓库
3. 平台自动检测 Astro 项目，使用默认构建设置
4. 配置自动部署（每次推送自动构建发布）

### 方式二：通过 CLI 部署

```bash
# 安装 CLI
npm install --global netlify-cli

# 构建
npm run build

# 部署
netlify deploy --prod
```

### 方式三：本地构建后上传

```bash
npm run build
# 将 dist/ 目录上传到你的服务器
```

## SSR 部署注意事项

如果需要按需渲染，需：

1. 安装对应适配器
2. 配置 `astro.config.mjs`
3. 确保托管平台支持 SSR

示例（Netlify SSR）：

```javascript
// astro.config.mjs
import { defineConfig } from 'astro/config';
import netlify from '@astrojs/netlify';

export default defineConfig({
  output: 'server',
  adapter: netlify(),
});
```

## 配置重定向

在部署时可能需要配置重定向规则。Astro 支持在配置文件中定义：

```javascript
// astro.config.mjs
export default defineConfig({
  redirects: {
    '/old-page': '/new-page',
    '/blog/[...slug]': '/articles/[...slug]',
  }
});
```

部分适配器会在构建时生成对应平台的重定向配置文件。

## 环境变量

```bash
# .env 文件
PUBLIC_API_URL=https://api.example.com
SECRET_API_KEY=xxx
```

- 以 `PUBLIC_` 开头的变量会被暴露给客户端
- 其他变量仅在服务端可用

在组件中使用：

```astro
---
const apiUrl = import.meta.env.PUBLIC_API_URL;
const apiKey = import.meta.env.SECRET_API_KEY;
---
```

## 常见问题

### 站点地图 (Sitemap)

```bash
npx astro add sitemap
```

安装后自动生成 `sitemap-index.xml`，需在 `astro.config.mjs` 中设置 `site` 属性。

### 图片优化

安装图片集成可自动优化图片：

```bash
npx astro add picture
```

### 构建输出目录

如需更改输出目录：

```javascript
// astro.config.mjs
export default defineConfig({
  outDir: './build',   // 默认 'dist'
});
```
